E-Bike Vehicle Control Unit

Vehicle Control Unit

Project Description

  • The Vehicle Control Unit (VCU) is the main controller of an electric bike, managing vehicle operation, the battery management system and the motor inverter.
  • It provides GNSS tracking and cellular connectivity for remote monitoring and control through a mobile app, and shows vehicle status on an RGB LCD.
  • Role Firmware Lead (Phase 1), Firmware Developer
  • Period Nov 2025 - Apr 2026
  • Team size 3

Key Features

  • Centralized control of vehicle operation and system states
  • Control and monitoring of the motor inverter and battery management system
  • Vehicle condition monitoring and fault handling
  • GNSS tracking and cellular connectivity
  • Vehicle information and status display on an RGB LCD

My Responsibilities

  • Analyzed requirements and designed the software architecture using UML
  • Designed the application layer that manages vehicle states and operation
  • Developed communication interfaces (I2C, UART, CAN) between the VCU and peripherals, including RFID, GNSS, cellular module, BMS and motor inverter
  • Developed a CAN stack for the motor inverter and BMS, and a firmware update over CAN following the UDS standard
  • Developed an RFID stack based on the NCI standard over I2C and SPI
  • Developed telematics features (remote monitoring, remote control, GNSS tracking) and vehicle I/O functions (RFID authentication, lighting, horn, turn signals)
  • Created unit, integration and system tests (Ceedling, RAM Monitor), and used CANoe to build CAN databases and simulate network nodes before hardware integration

Technical Challenges & Solutions

  • Shared I2C and CAN buses across multiple tasks: several FreeRTOS tasks needed to access the same I2C and CAN buses, which risked race conditions, deadlocks and priority inversion. I designed an event-driven architecture in which a dedicated task owns and controls each bus, and other tasks send events to it instead of accessing the hardware directly. This removes contention on the buses, keeps the tasks decoupled, and meets timing requirements.
  • Reliable GNSS and cellular data over UART: continuous data streams from the GNSS and cellular modules could be lost when tasks were busy. I designed a ring-buffer-based UART mechanism that receives data in the background and lets tasks process it without losing bytes.
